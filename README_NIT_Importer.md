# NIT² by FIZYK

Утиліта імпортує **теми уроків** і **домашні завдання** з `.xlsx` у електронний журнал НІТ.

## Завантаження зі шкільного комп'ютера

Репозиторій: [github.com/PashaNULP/NIT_Homework_Importer](https://github.com/PashaNULP/NIT_Homework_Importer)

Найпростіше на Windows без Git:

1. Відкрийте посилання на репозиторій.
2. Натисніть **Code → Download ZIP**.
3. Розпакуйте ZIP у звичайну папку, наприклад `C:\NIT2`.
4. Запустіть `Встановити NIT Windows.bat` і виконайте інструкції нижче.

Якщо Git уже встановлений:

```powershell
git clone https://github.com/PashaNULP/NIT_Homework_Importer.git
cd NIT_Homework_Importer
```

Оновлення встановленої через Git копії:

```powershell
git pull
```

## Що вміє

- автоматично отримує активний навчальний рік і `scheduleId` 1/2 семестру;
- автоматично показує лише твої журнали (`isMyJournal=true`);
- отримує всі уроки вибраного журналу;
- формує звіт із кількістю та датами уроків у всіх твоїх журналах;
- читає Excel із колонками `Тема уроку`, `Домашнє завдання` і, бажано, `Дата`;
- підтримує 3 режими: тільки ДЗ / тільки пропуски / синхронізація теми + ДЗ;
- завжди показує preview перед записом;
- перед записом створює локальний перевірений JSON-backup поточного стану журналу;
- порожні клітинки Excel не стирають дані НІТ, якщо явно не передати `--allow-clear`.

### Локальний вебінтерфейс

Вебінтерфейс вміє:

- давати кожному браузеру окремий вхід у власний обліковий запис НІТ;
- автоматично визначати `userId` учителя після входу;
- завершувати поточну сесію кнопкою виходу у правій частині шапки;
- перемикати семестр і журнал класу;
- показувати кількість заповнених та незаповнених уроків;
- будувати календар із правильною кількістю уроків на кожну дату;
- показувати окремими рядками кілька уроків одного дня;
- завантажувати Excel і показувати preview старих та нових значень;
- завантажувати готовий Excel-шаблон для вибраного класу й предмета;
- імпортувати ДЗ/теми після перевірки Preview та підтвердження кнопкою;
- створювати JSON-backup у папці `backups` перед першим записом;
- знаходити червоні трикутники, вибирати клас та окремі рядки;
- ставити вибрані позначки «н» після підтвердження у діалозі;
- експортувати вибраний журнал у Excel або JSON;
- показувати персональний тижневий розклад учителя з НІТ;
- експортувати JSON тижневого розкладу всіх активних учителів без контактних даних;
- зберігати останні отримані тижні для офлайн-перегляду;
- вести локальні профілі дзвінків «Звичайний», «Скорочений» та власні.

Перевірити активну для проєкту версію Python:


Запуск:

```bash
.venv/bin/python nit_web.py
```

### Встановлення на Windows і доступ у шкільній мережі

1. Встановіть **Python 3.13 (64-bit)** з python.org і ввімкніть пункт
   `Add python.exe to PATH`.
2. Скопіюйте всю папку NIT² на комп'ютер, який буде сервером.
3. Двічі запустіть `Встановити NIT Windows.bat`.
4. Перевірте `nit_config.local.json`: для поточної школи `school_id` має бути `97`.
   `user_id` для вебверсії не потрібен — він визначається для кожного входу.
5. Двічі запустіть `Запустити NIT Windows.bat` і не закривайте його вікно.

Якщо копію було встановлено до додавання Windows-бази часових поясів і запуск
показує `No module named 'tzdata'`, виконайте у PowerShell з папки проєкту:

```powershell
.\.venv\Scripts\python.exe -m pip install tzdata
```

Лаунчер покаже IPv4-адресу сервера. На інших комп'ютерах школи відкрийте:

```text
http://IP_СЕРВЕРА:8080
```

Якщо сторінка не відкривається, у Windows Defender Firewall дозвольте Python
приймати з'єднання в **приватній** мережі або створіть вхідне правило для TCP
порту `8080`. Комп'ютери мають бути в одній локальній мережі, а мережевий
профіль Windows — `Private`.

Кожен учитель входить власним email і паролем НІТ. Сесії браузерів не
змішуються, пароль не зберігається, а токени залишаються лише в пам'яті
серверного Python-процесу. Кнопка виходу видаляє тільки поточну сесію; після
перезапуску сервера всі користувачі входять повторно.

> Для постійного розгортання краще додати HTTPS через локальний reverse proxy.
> Звичайний `http://` придатний для початкового тесту в довіреній шкільній LAN,
> але не для публікації сервера в інтернеті. Не відкривайте порт `8080` на роутері.

Операції запису захищені від повторного натискання, завжди показують preview,
створюють backup і вимагають окремого підтвердження у діалозі. Вводити слова
`ЗАПИСАТИ` або `ПІДТВЕРДИТИ` у вебінтерфейсі більше не потрібно. Безпосередньо
перед кожною зміною застосунок повторно читає урок із НІТ і порівнює його зі
станом, на якому побудовано Preview. Якщо дані вже змінилися в іншій вкладці
або іншим учителем, пакет зупиняється. Після кожного запису результат повторно
читається з НІТ і перевіряється. Якщо API-запит завершиться неоднозначною
мережевою помилкою, запис автоматично не повторюється: спочатку перевіряється
фактичний стан, щоб не створити дубль.

Файл `lessons.xlsx`, створений кнопкою експорту звіту, призначений для аналізу
й не містить колонок теми та ДЗ. Для подальшого імпорту використовуйте кнопку
`Завантажити шаблон` на вкладці `Імпорт Excel`.

З'явиться головне меню:

```text
1. Імпортувати теми та домашні завдання з Excel
2. Переглянути кількість і дати уроків
3. Підтвердити відсутності (червоні трикутники → «н»)
4. Вийти
```

Для звіту додатково можна вибрати перегляд у терміналі або збереження в
Excel/JSON. Для звіту та підтвердження відсутностей меню також запропонує
обидва семестри, перший або другий. Параметри командного рядка нижче
залишаються доступними для швидкого запуску потрібного режиму без меню.

Після вибору імпорту з'явиться вибір Excel-файлу. Якщо file picker не
відкриється, скрипт попросить вставити шлях.

Або одразу передати файл:

```bash
python3 nit_homework_v2.py "/шлях/до/Домашні_завдання.xlsx"
```

Після вибору дії з'явиться меню авторизації:

```text
1. Використати збережену сесію з macOS Keychain (якщо вона є)
2. Увійти через email і пароль
3. Зчитати Bearer token із буфера обміну
4. Видалити збережену сесію (якщо вона є)
5. Скасувати
```

Під час входу через email і пароль скрипт використовує офіційний OAuth endpoint
НІТ для отримання тимчасового access token. Пароль вводиться приховано,
використовується лише для запиту авторизації та не записується у файл або
backup. У захищеному macOS Keychain зберігається лише refresh token, розділений
на короткі записи через системне обмеження інтерактивного вводу Keychain. Під
час наступного запуску програма автоматично отримує новий тимчасовий access token.
Пароль у Keychain не зберігається. Якщо Keychain недоступний, поточний вхід усе
одно працює до завершення програми.

Поки вебінтерфейс відкритий, він перевіряє строк дії окремої сесії щохвилини й
поновлює access token приблизно за п'ять хвилин до завершення. Перед читанням
або записом важливих даних виконується додаткова перевірка. Якщо refresh token
також недійсний, застосунок не починає запис і просить увійти повторно.

Для роботи з Keychain скрипт використовує системну утиліту macOS `security`,
тому окремий Python-пакет для цього не потрібен. Якщо пункт збереженої сесії не
з'являється, один раз увійди через email і пароль:

```bash
python3 nit_homework_v2.py
```

> Не передавай робочий token або пароль у ChatGPT чи іншим людям. Вводь їх
> тільки локально у своєму Terminal.

## Формат Excel

Найнадійніший формат:

| Дата | Тема уроку | Домашнє завдання |
|---|---|---|
| 01.09.2025 | Тепловий стан тіл... | § 10 — ... |

Колонка `Дата` є головним ключем. Підтримуються дати `01.09.2025`, `2025-09-01` або справжні Excel dates.

Якщо в один день у класу може бути два уроки того самого предмета, можна додати колонку `Урок` — номер уроку в розкладі.

## Персональний розклад

Вкладка `Розклад` має три режими: `Тиждень`, `Місяць` і `Дзвінки`.
Колишній окремий календар перенесено в режим `Місяць` без втрати функцій:
він так само показує уроки всіх класів, перемикання місяців і деталі вибраного
дня. Режим `Тиждень` використовує підтверджений read-only endpoint:

```http
GET /api/v1/dashboard/teacher-diary?date=Mon%20Nov%2002%202026
```

Параметр — понеділок потрібного тижня в англійському форматі, який використовує
вебзастосунок НІТ. Відповідь містить конкретні дати тижня та уроки з полями
`number`, `subject`, `className`, `isFds`. Тому сусідні тижні зберігаються й
показуються окремо, а не перетворюються на незмінний шаблон.

Відповідь `teacher-diary` не містить часу або кабінету. Офіційні дзвінки
отримуються окремо з повної моделі активного навчального року:

```http
GET /api/v1/academic-years?take=10&skip=0
```

Масив `lessons` містить `number`, `name`, `fromTime`, `toTime` і `type`.
В інтерфейсі джерело `НІТ · офіційні` вибирається автоматично та доступне лише
для читання. Для активного року API повернув один звичайний режим; окремого
скороченого набору в підтверджених даних немає.

Локальні профілі залишаються альтернативою для скорочених або спеціальних
днів. Початкові профілі навмисно порожні: застосунок не вигадує години.
Доступні профілі `Звичайний`, `Скорочений`, створення власних профілів,
додавання та редагування уроків. Локальні дзвінки ніколи не надсилаються до НІТ.

Отримані тижні кешуються у `.nit2_data/schedule` окремо для кожного профілю
користувача. Ідентифікатор у назві файлу хешований, токенів у кеші немає,
каталог і файли мають обмежені права доступу. Час останнього оновлення та
джерело (`НІТ` або `збережена копія`) показуються в інтерфейсі. Якщо НІТ став
недоступним, уже авторизований застосунок може перейти на кеш цього користувача.

Блок `Зараз і далі` та віджет на `Огляді` використовують часовий пояс
`Europe/Kyiv` і за замовчуванням беруть офіційний час НІТ. Офіційні дзвінки
також кешуються для офлайн-перегляду.

### Старий файл без дати

Поточний файл `Домашні_завдання_фізика_8_клас_Баряхтар_1_семестр.xlsx` теж підтримується. Якщо колонки `Дата` немає, скрипт зіставляє рядки з уроками НІТ **за порядком**, але лише коли кількість рядків Excel точно дорівнює кількості уроків у НІТ. Перед записом обов'язково перевір preview.

## Режими

При запуску скрипт запропонує:

1. **Тільки домашні** — змінює `homework`, тему не чіпає.
2. **Заповнити пропуски** — записує тему/ДЗ тільки там, де відповідне поле НІТ порожнє.
3. **Синхронізувати тему + ДЗ** — бере непорожні тему й ДЗ з Excel та замінює ними значення НІТ.

## Безпека

У вебінтерфейсі достатньо підтвердити операцію кнопкою в окремому діалозі.
Консольна версія з міркувань сумісності досі просить ввести:

```text
ЗАПИСАТИ
```

До першого PUT/POST створюється файл у папці `backups` виду:

```text
nit_backup_8-А_Фізика_20260818_170000_123456_a1b2c3.json
```

Він містить стан уроків **до змін**, але не містить Bearer token. Файл має
унікальне ім'я, створюється атомарно, отримує права `600`, а папка — `700`.
Усередині є версія формату та SHA-256 для перевірки цілісності. Після запису
backup одразу перечитується і перевіряється; якщо це не вдалося, API-зміни не
починаються. Старі backup-файли не переміщуються й не видаляються автоматично.

Автоматичного відновлення в офіційний журнал навмисно немає: формат backup
придатний для перевірки та ручного відновлення, але будь-яке відновлення має
спершу показати окремий Preview і вимагати явного підтвердження.

## Звіт про кількість і дати уроків

Щоб отримати дані одразу для всіх класів і предметів, де твій журнал має
`isMyJournal=true`, запусти:

```bash
python3 nit_homework_v2.py --lesson-report
```

Без `--semester` звіт охоплює обидва доступні семестри. Для одного семестру:

```bash
python3 nit_homework_v2.py --lesson-report --semester 1
```

Результат можна одночасно зберегти у Excel (окремі аркуші `Уроки` та
`Підсумок`) або JSON:

```bash
python3 nit_homework_v2.py --lesson-report --report-output lessons.xlsx
python3 nit_homework_v2.py --lesson-report --report-output lessons.json
```

Цей режим лише читає дані з НІТ, не потребує вхідного Excel-файлу та нічого
не змінює в журналі. Скрипт проходить усі сторінки журналу та рахує окремі
колонки уроків, тому враховуються також уроки без заповненої теми чи домашнього
завдання і два уроки в один день рахуються як два.
В Excel дата записується явним текстом у форматі `ДД.ММ.РРРР`, без залежності
від регіональних налаштувань табличного редактора.
У терміналі `✓` означає наявний календарний план, а `○` — ще не заповнений.

## Підтвердження відсутностей

Щоб знайти червоні трикутники, залишені класним керівником, і підтвердити їх
позначкою `н`:

```bash
python3 nit_homework_v2.py --confirm-absences
```

Після завантаження нагадувань з'явиться меню з класами та кількістю позначок.
Можна вибрати один клас або всі класи. Щоб одразу вказати клас без меню:

```bash
python3 nit_homework_v2.py --confirm-absences --class-name "10-А"
```

Для одного семестру:

```bash
python3 nit_homework_v2.py --confirm-absences --semester 1
```

Перед записом скрипт показує клас, предмет, дату, номер уроку та скорочений ID
учня. У вебінтерфейсі використовується звичайний діалог із кнопками; консольна
версія досі просить `ПІДТВЕРДИТИ`. Параметр `--yes` не вимикає CLI-підтвердження,
оскільки позначки потрапляють до офіційного журналу. Перед першим запитом створюється локальний JSON-backup
списку нагадувань. Перед кожною позначкою застосунок ще раз перевіряє клітинку.
Уже підтверджена `н` пропускається, а клітинка з оцінкою, іншою позначкою,
неоднозначним або неповним станом ніколи не перезаписується. Тому повторний
запуск є ідемпотентним.

Корисні приклади:

```bash
# Тільки домашні
python3 nit_homework_v2.py file.xlsx --mode homework

# Тема + ДЗ
python3 nit_homework_v2.py file.xlsx --mode sync

# 1 семестр без запитання про семестр
python3 nit_homework_v2.py file.xlsx --semester 1

# У preview показувати лише те, що реально зміниться
python3 nit_homework_v2.py file.xlsx --only-changed
```

## Якщо НІТ оновить вебзастосунок

У скрипті поточна версія клієнта стоїть як `v1.10.2.10`. Її можна перевизначити без редагування коду:

```bash
export NIT_CLIENT_VERSION="v1.10.2.10"
```

Так само можна перевизначити `NIT_SCHOOL_ID` та `NIT_USER_ID`. Для окремого
набору облікових даних CLI можна задати профіль:

```bash
export NIT_PROFILE="teacher-2"
```

Профіль змінює назву запису сесії в Keychain, тому сесії різних користувачів
не змішуються. Без цієї змінної використовується старий запис `nit.school`,
тобто поточний спосіб запуску повністю сумісний.

`school_id` за замовчуванням читається з локального `nit_config.local.json`.
Цей файл ігнорується Git. Вебверсія після OAuth-входу отримує власний `userId`
учителя через `GET /api/v1/users/my-permissions` і перевіряє, що користувач має
активний доступ до налаштованої школи. Тому спільний сервер не використовує
один `user_id` для всіх. Поле `user_id` у локальному конфігу залишене лише для
сумісності з CLI.

## Технічна структура

- `nit_web.py` — локальний NiceGUI-інтерфейс;
- `nit_homework_v2.py` — CLI, HTTP-клієнт НІТ та перевірені функції сумісності;
- `nit_core.py` — спільні сценарії Preview, імпорту, журналу та відсутностей;
- `nit_auth.py` — конфігурація користувача й незалежний інтерфейс сховища сесій;
- `nit_backup.py` — атомарні backup та перевірка їх цілісності;
- `nit_schedule.py` — нормалізація персонального розкладу, захищений кеш і локальні дзвінки;
- `tests/` — офлайн-регресійні тести з підробленими відповідями API.

`nit_homework_debug.py` залишено як окремий старий діагностичний сценарій. Він
не імпортується робочим вебінтерфейсом або CLI та не є джерелом актуальної
бізнес-логіки. Великий файл розділяється поступово, щоб не ламати перевірені
маршрути API та сценарії macOS.

Абстракція `SessionStore` не залежить від операційної системи. CLI на macOS
використовує Keychain, а багатокористувацька вебверсія — окреме потокобезпечне
сховище в пам'яті для кожного браузера. Завдяки цьому Windows Credential
Manager на шкільному сервері не потрібен.

## Офлайн-перевірка

Тести не звертаються до справжнього НІТ і не записують дані в журнал:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Вони перевіряють Excel зі звичайними та подвійними уроками, конфлікт після
Preview, частковий збій пакета, підтвердження після мережевої помилки,
повторний запуск відсутностей, захист оцінок, backup/права/контрольну суму та
сумісність авторизації.

## Відоме обмеження API

API НІТ не надає відомого нам номера версії запису або умовного PUT на кшталт
`If-Match`. Тому застосунок робить максимально безпечну optimistic-перевірку
безпосередньо перед записом і верифікацію одразу після нього, але теоретично
залишається дуже мале вікно між останнім GET і PUT/POST. При конфлікті або
непідтвердженому результаті пакет негайно зупиняється та показує кількість уже
завершених операцій і шлях до backup.
